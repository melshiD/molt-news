01 / Overview

What Claude Code Is and How It Works

Claude Code is Anthropic's agentic coding assistant, available as a CLI tool, VS Code/JetBrains extension, and web interface at claude.ai/code. Unlike a chat interface bolted on top of an editor, Claude Code is built around a persistent shell session that gives the model direct tool access: reading files, executing shell commands, running tests, browsing the web, and committing to git — all with user-configurable permission gates.

The core insight is that Claude Code treats your working directory as a first-class citizen. Every invocation starts from a directory context; the model can read, edit, and create files there without copy-pasting. The agentic loop runs tool calls until it reaches an answer or needs user confirmation, making it fundamentally different from a single-shot code generation API.

For automation, the critical feature is --print (or -p) mode: a non-interactive flag that accepts a prompt, executes the agentic loop, prints the result to stdout, and exits. This makes Claude Code composable with shell scripts, CI pipelines, cron jobs, and any system that can call a subprocess.

Architecture Note

Claude Code runs locally as a Node.js CLI. It calls the Anthropic API directly (or your configured proxy) and uses the Claude 3.x / Claude 4.x model family. The model receives tool results inline and continues the agentic loop, making each invocation potentially multi-step. In print mode, this happens headlessly and the final response goes to stdout.

Key Insight 01
Print mode is the automation primitive
Every automation pattern described in this document builds on claude -p "...". Once you understand that flag, you can script Claude Code the same way you'd script git, jq, or any other CLI tool.
Key Insight 02
Permissions are the safety layer for automation
The --dangerously-skip-permissions flag exists for fully-trusted automation environments (like a sandboxed CI container). In dev, prefer explicit allowlists via .claude/settings.json to grant only the permissions a given workflow needs.
Key Insight 03
CLAUDE.md is the project's long-term memory
Place a CLAUDE.md file at the root of a repo to give Claude Code persistent context: conventions, architecture, off-limit files, and anything that would otherwise require repeated prompting. This file is loaded automatically on every invocation in that directory.
02 / Installation

Installation & Initial Setup

Claude Code requires Node.js 18+ and an Anthropic API key (or Claude.ai Pro/Max subscription for browser-based billing).

  1. Install via npm
    Install globally so the claude command is available everywhere. The package is @anthropic-ai/claude-code.
    bash
    # Install globally
npm install -g @anthropic-ai/claude-code

# Verify install
claude --version
  2. Authenticate
    Run claude once interactively to authenticate. You can use OAuth with a Claude.ai account or paste in an Anthropic API key directly.
    bash
    # Interactive auth — opens browser or prompts for API key
claude

# Or set API key in environment for automation
export ANTHROPIC_API_KEY=sk-ant-...
# Or pass inline
claude --api-key sk-ant-... -p "hello"
  3. Create a project CLAUDE.md
    Initialize a CLAUDE.md at the root of any project to give Claude Code persistent context — or use /init inside an interactive session to generate one automatically.
    CLAUDE.md (example)
    # Project: my-api

## Stack
Node.js 20, TypeScript, Prisma, PostgreSQL

## Conventions
- All files use 2-space indent, no semicolons
- Tests live in __tests__/ using Vitest
- Never modify migrations directly

## Off-limits
- Do not edit .env files
- Do not commit secrets
  4. Configure permissions for your project
    Create .claude/settings.json to pre-approve specific tools or commands so automation workflows don't prompt interactively.
    .claude/settings.json
    {
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git add *)",
      "Bash(git commit *)",
      "Bash(git status)",
      "Read(**)",
      "Edit(**)",
      "Write(**)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push --force *)"
    ]
  }
}
03 / CLI Reference

CLI Flags Reference

The claude command accepts the following flags. The most important for automation are -p (print mode), --output-format, and --dangerously-skip-permissions.

Flag Short Description Automation use
--print -p Run non-interactively. Accepts prompt, executes, prints to stdout, exits. Core automation flag
--output-format Output format: text (default), json, or stream-json. JSON includes metadata, token counts, session ID. Parsing pipelines
--model Override default model (e.g. claude-opus-4-5, claude-sonnet-4-5). Cost/speed tradeoffs
--api-key Provide Anthropic API key inline. Overrides ANTHROPIC_API_KEY env var. Multi-key setups
--system-prompt -s Prepend a custom system prompt to every invocation. Domain-specific agents
--append-system-prompt Append to the existing system prompt rather than replacing it. Layered instructions
--continue -c Resume the most recent conversation session. Multi-step workflows
--resume -r Resume a specific session by ID. Named sessions
--max-turns Limit how many agentic turns the model can take before stopping. Safety for automation
--allowedTools Comma-separated list of tools the model may use in this invocation. Scoped automation
--disallowedTools Comma-separated list of tools to block. Safety restrictions
--dangerously-skip-permissions Bypass all permission prompts. Use only in isolated, trusted CI environments. Headless CI
--no-color Disable ANSI color codes in output. Log parsing
--verbose Show tool call details and debug information. Debugging automations
--input-format Treat stdin as text or stream-json for chaining Claude invocations. Agent pipelines
--add-dir Add an additional directory to Claude's allowed file scope. Multi-repo tasks
04 / Interactive Mode

Slash Commands (Interactive Mode)

In interactive mode, slash commands let you control the session, manage context, configure settings, and invoke built-in skills. These cannot be used in -p print mode — they are interactive-only affordances.

/help
Show all available commands and keybindings
/clear
Clear conversation history and start fresh
/compact
Summarize and compress conversation to save context window space
/save
Save current conversation to a markdown file
/resume
Resume a previous conversation by session ID
/init
Generate a CLAUDE.md file for the current project
/review
Run a built-in code review skill on current branch changes
/pr
Generate a pull request from current branch diff
/cost
Show token usage and estimated cost for this session
/doctor
/config
Check Claude Code health / view and edit configuration
/mcp
Manage MCP server connections and tools
/memory
View and edit project and user memory files
/bug
File a bug report to the Claude Code team
/permissions
View or update tool permission allowlist/denylist
/fast
Toggle Fast mode (Opus 4 with faster output streaming)
Custom Skills

Skills are user-defined slash commands stored as markdown files in ~/.claude/commands/ (user-level) or .claude/commands/ (project-level). Each file becomes a /skill-name command. The file body is the prompt; it can include $ARGUMENTS for user-provided input. This is how teams build shared, reusable Claude Code workflows.

.claude/commands/changelog.md
# Generates a changelog entry from recent git commits
Look at the git log since the last tag and write a changelog entry
in the style of keep-a-changelog.org for version $ARGUMENTS.
Group by: Added, Changed, Fixed, Removed.
Output only the markdown block, no preamble.

Invoke with: /changelog 2.4.0

05 / Print Mode

Non-Interactive (Print) Mode

Print mode is the foundation of all Claude Code automation. Pass -p or --print with a prompt to get a single response to stdout and exit. Claude Code still executes the full agentic loop — it reads files, runs commands, etc. — but doesn't wait for user input.

bash — basic print mode usage
# Single question, text output
claude -p "What does the init() function in src/server.ts do?"

# Pipe input as context
cat error.log | claude -p "Summarize the errors in this log and suggest fixes"

# JSON output with metadata
claude -p "Review this PR diff" --output-format json | jq '.result'

# Limit agentic turns (prevents runaway loops)
claude -p "Fix the failing test in tests/auth.test.ts" --max-turns 5

# Restrict to read-only tools (no writes)
claude -p "Describe the database schema" \
  --allowedTools Bash,Read,Grep,Glob

# Custom system prompt for a specific role
claude -p "Review the security of this code" \
  --system-prompt "You are a security auditor. Be conservative and explicit."
stdin Piping

Claude Code reads stdin when piped to. This lets you send file contents, diffs, logs, or any text as additional context without needing to specify file paths. The model receives stdin as part of the human turn, before your prompt.

git diff HEAD~1 | claude -p "Write a commit message for these changes"

JSON Output Mode

--output-format json returns a structured object instead of plain text. This is useful when you need to parse Claude's response programmatically, access token counts, or chain invocations. The stream-json variant emits newline-delimited JSON events as they occur.

JSON response shape
{
  "type": "result",
  "subtype": "success",
  "result": "The main findings are...",
  "session_id": "sess_01Abc...",
  "total_cost_usd": 0.0042,
  "usage": {
    "input_tokens": 1240,
    "output_tokens": 380,
    "cache_read_input_tokens": 850,
    "cache_creation_input_tokens": 0
  }
}
06 / Hooks System

Hooks: Intercept Every Tool Call

The hooks system lets you run shell commands in response to Claude Code events — before or after tool use, when the session starts or ends, when a message is submitted. Hooks are configured in .claude/settings.json (project-level) or ~/.claude/settings.json (user-level).

Hooks receive event context as JSON on stdin and can output JSON to modify behavior, or simply run side effects like logging. A hook that exits non-zero blocks the tool call (for PreToolUse hooks) or the session exit (for Stop hooks).

.claude/settings.json — hooks configuration
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{
          "type": "command",
          "command": "bash .claude/hooks/pre-bash.sh"
        }]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{
          "type": "command",
          "command": "bash .claude/hooks/post-edit.sh"
        }]
      }
    ],
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "node .claude/hooks/on-stop.js"
      }]
    }],
    "Notification": [{
      "hooks": [{
        "type": "command",
        "command": "bash .claude/hooks/notify.sh"
      }]
    }]
  }
}
PreToolUse
Runs before every tool call. Can block execution by returning {"decision": "block"}. Use for auditing, guardrails, or transforming tool inputs.
PostToolUse
Runs after every tool call completes. Receives the tool result. Use for logging, triggering side effects (format, lint), or enriching results.
Stop
Runs when Claude Code is about to stop (either done or waiting for input). Use for notifications, cleanup, or summaries.
Notification
Fires when Claude Code wants to notify the user (e.g., awaiting input). Use for Slack alerts, desktop notifications, or paging.
bash — .claude/hooks/post-edit.sh (auto-format on every file edit)
#!/bin/bash
# Receives tool result on stdin as JSON
TOOL_INPUT=$(cat)
FILE=$(echo "$TOOL_INPUT" | jq -r '.tool_input.file_path // empty')

if [[ "$FILE" == *.ts ]] || [[ "$FILE" == *.tsx ]]; then
  npx prettier --write "$FILE" 2>/dev/null
fi

if [[ "$FILE" == *.py ]]; then
  python -m black "$FILE" 2>/dev/null
fi
07 / Extensions

MCP: Extending Claude Code's Tool Surface

The Model Context Protocol (MCP) is an open standard for connecting AI models to external data sources and tools. Claude Code ships with built-in MCP support: add any MCP server and its tools become available to the model alongside Claude Code's native tools (Bash, Read, Edit, Grep, etc.).

MCP servers run as local processes (over stdio) or remote HTTP services. Claude Code's MCP config lives in ~/.claude/claude_desktop_config.json (shared with Claude Desktop) or inline in project settings.

claude_desktop_config.json — MCP server setup
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "ghp_..." }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres",
               "postgresql://localhost/mydb"]
    },
    "slack": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-slack"],
      "env": { "SLACK_BOT_TOKEN": "xoxb-..." }
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem",
               "/home/user/projects"]
    }
  }
}
Popular MCP Servers

GitHub — create/review PRs, manage issues, fetch diffs, comment on code. Postgres / SQLite — query databases, inspect schemas, generate migrations. Slack — send messages, read channels, post alerts. Puppeteer — web scraping and browser automation. Linear / Jira — issue tracking. AWS / GCP — cloud resource inspection and management.

08 / Memory

Memory System & CLAUDE.md

Claude Code has a layered memory system. At the bottom is the project-level CLAUDE.md, automatically loaded on every invocation in that directory. At the top is user-level memory at ~/.claude/CLAUDE.md. Between them, individual sessions can persist memory files that are loaded in future conversations.

~/.claude/CLAUDE.md
User-level memory loaded in every Claude Code session regardless of directory. Put your personal preferences, global style rules, and preferred tools here.
<project>/CLAUDE.md
Project-level memory. Stack: architecture, conventions, off-limits files, build commands. Committed to git so the whole team benefits automatically.
<subdir>/CLAUDE.md
Subdirectory memory, loaded when Claude Code navigates into that subdirectory. Use for per-service or per-module context in monorepos.
~/.claude/projects/…/memory/
Per-project memory files managed by the agentic loop. Includes user profile notes, feedback, project state, and reference pointers persisted across sessions.
CLAUDE.md — comprehensive example for a TypeScript API
# Project: payments-api

## Architecture
Express 4 + TypeScript + Prisma + PostgreSQL 16.
Services in src/services/, routes in src/routes/, types in src/types/.
Never import across service boundaries — pass through the router layer.

## Build & test
- `npm run dev` — start with hot reload
- `npm test` — Vitest (must pass before committing)
- `npm run typecheck` — tsc --noEmit

## Code conventions
- 2-space indent, no semicolons, single quotes
- All async functions return typed Promises, never `any`
- Errors: throw PaymentError (see src/errors.ts), never plain Error

## Off-limits
- Never edit prisma/migrations/ directly
- Never commit .env or .env.local
- Do not change the Stripe webhook signature verification logic

## Common tasks
- Add a new route: copy src/routes/health.ts as a template
- Add a migration: `npx prisma migrate dev --name description`
09 / Git Integration

Git Workflow Automation

Claude Code has native git awareness: it reads git status, diff, log, and blame to understand code history. Combined with print mode, this makes Claude Code an extremely capable git automation layer — from writing commit messages to running pre-commit checks to drafting PR descriptions.

bash — git automation recipes
# Generate a commit message from staged diff
git diff --cached | claude -p "Write a conventional commit message for these changes.
Format: type(scope): description. Types: feat, fix, refactor, chore, docs."

# Auto-commit with Claude-generated message
MSG=$(git diff --cached | claude -p "Write a one-line conventional commit message")
git commit -m "$MSG"

# Draft a PR description from branch diff vs main
git diff main...HEAD | claude -p "Write a PR description with:
## Summary (3 bullet points)
## Test plan (checklist)
## Breaking changes (if any)"

# Code review before pushing
git diff main...HEAD | claude -p \
  "Review this diff for: logic errors, missing error handling,
   security issues, and anything that will fail in production.
   Output a numbered list. Exit 1 if critical issues found."
if [ $? -ne 0 ]; then echo "Review failed" && exit 1; fi

# Changelog entry for a release
git log v2.3.0..HEAD --oneline | claude -p \
  "Write a CHANGELOG.md entry for version 2.4.0 using keep-a-changelog format"

Git Hooks Integration

Claude Code can run inside native git hooks for automatic pre-commit quality checks. The key is using --allowedTools to restrict to read-only tools and keeping --max-turns low so hooks complete quickly.

.git/hooks/pre-commit
#!/bin/bash
# AI-powered pre-commit check
set -e

DIFF=$(git diff --cached)
if [ -z "$DIFF" ]; then exit 0; fi

echo "Running Claude Code pre-commit review..."

RESULT=$(echo "$DIFF" | claude -p \
  "You are a strict pre-commit reviewer.
   Check this diff ONLY for:
   1. Hardcoded secrets or API keys
   2. console.log / debug statements left in production code
   3. TODO comments that block shipping
   4. Obvious syntax errors

   If any issues found, output them and exit with code 1.
   If clean, output 'LGTM' only." \
  --allowedTools "" \
  --max-turns 1 \
  --no-color)

echo "$RESULT"

if echo "$RESULT" | grep -qi "LGTM"; then
  exit 0
else
  exit 1
fi
10 / CI/CD

CI/CD Integration

Claude Code works cleanly in CI environments. The key ingredients are: ANTHROPIC_API_KEY as a secret, --dangerously-skip-permissions for headless operation (since there's no user to approve tool calls), and --no-color for clean log output.

.github/workflows/claude-review.yml
name: Claude Code PR Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      pull-requests: write
      contents: read

    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - uses: actions/setup-node@v4
        with: { node-version: '20' }

      - name: Install Claude Code
        run: npm install -g @anthropic-ai/claude-code

      - name: Run AI Code Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          DIFF=$(git diff origin/main...HEAD)
          REVIEW=$(echo "$DIFF" | claude -p \
            "Review this PR diff. Identify:
             - Logic errors or edge cases missed
             - Missing input validation
             - Security vulnerabilities (SQL injection, XSS, etc.)
             - Performance issues
             - Missing tests for changed code
             Format as GitHub markdown with severity labels." \
            --dangerously-skip-permissions \
            --no-color \
            --max-turns 5)
          echo "$REVIEW" > review.md

      - name: Post Review Comment
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const review = fs.readFileSync('review.md', 'utf8');
            await github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `## Claude Code Review\n\n${review}`
            });
Security Note

--dangerously-skip-permissions should only be used in isolated CI containers. Never use it in production environments where the model could affect real infrastructure. In CI, pair it with narrow --allowedTools to restrict what the model can actually do.

.github/workflows/security-scan.yml
name: AI Security Scan

on:
  push:
    branches: [main]

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm install -g @anthropic-ai/claude-code
      - name: Security Audit
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          claude -p \
            "Perform a security audit of this codebase.
             Focus on OWASP Top 10. Check:
             1. All route handlers for injection vulnerabilities
             2. Authentication and authorization logic
             3. Secrets or credentials in code
             4. Dependencies with known CVEs (check package.json)
             Output findings as JSON: [{severity, file, line, issue, recommendation}]" \
            --dangerously-skip-permissions \
            --output-format json \
            --no-color | jq '.result' > security-report.json

      - uses: actions/upload-artifact@v4
        with:
          name: security-report
          path: security-report.json
11 / Scheduled Tasks

Cron Jobs & Scheduled Workflows

Claude Code's print mode is perfectly suited for cron jobs — periodic tasks that run without user interaction. Common patterns include daily dependency audits, weekly code quality reports, automated documentation updates, and data pipeline health checks.

crontab — example scheduled Claude tasks
# Daily at 08:00: check for outdated dependencies and create a ticket
0 8 * * * cd /srv/myapp && \
  claude -p "Run npm outdated. For any packages more than 2 major versions behind,
  create a GitHub issue via the GitHub MCP tool with a migration checklist." \
  --dangerously-skip-permissions >> /var/log/claude-deps.log 2>&1

# Every Monday 09:00: weekly code quality report emailed to team
0 9 * * 1 cd /srv/myapp && \
  claude -p "Analyze the git commits from the past 7 days.
  Summarize: lines changed, test coverage trend, top contributors,
  most modified files, and any patterns worth noting.
  Send a summary to #engineering via the Slack MCP tool." \
  --dangerously-skip-permissions

# Every 15 minutes: pipeline health monitor
*/15 * * * * cd /srv/pipeline && \
  claude -p "Check the last 50 lines of logs/pipeline.log.
  If any ERROR lines found, post a Slack alert to #ops-alerts
  with the error details and the last successful run timestamp." \
  --dangerously-skip-permissions --max-turns 3

# First of each month: auto-update API docs from code
0 10 1 * * cd /srv/myapp && \
  claude -p "Read all route files in src/routes/. Update docs/api.md to reflect
  the current endpoints, parameters, and response shapes.
  Commit the changes with message 'docs: auto-update API reference'." \
  --dangerously-skip-permissions

Claude Code's Built-in Schedule Skill

Claude Code also ships with a /schedule skill for creating scheduled remote agents directly from the CLI. These agents run on a cron schedule and can be managed (listed, updated, deleted) without editing crontab manually.

claude interactive — using /schedule
# Inside an interactive Claude Code session:

# Schedule a daily report
/schedule run every day at 9am: \
  "Check our GitHub repo for any PRs open longer than 5 days. \
   Post a reminder to #dev-reviews on Slack."

# Schedule a one-time task
/schedule run once tomorrow at 2pm: \
  "Run the database migration script and verify row counts match."

# List scheduled routines
/schedule list

# Use /loop for self-paced recurring work in the current session
/loop check build status every 5 minutes until green

Batch Processing Multiple Repositories

For multi-repo or monorepo work, loop over directories and invoke Claude Code in each, passing the project path as context.

bash — batch across multiple repos
#!/bin/bash
# Run security audit across all microservices

REPOS=(/srv/services/*)
REPORT=""

for REPO in "${REPOS[@]}"; do
  [ -d "$REPO" ] || continue
  echo "Auditing $REPO..."

  RESULT=$(cd "$REPO" && claude -p \
    "Security audit: check for hardcoded secrets, SQL injection
     risks, and missing input validation. Output JSON array." \
    --dangerously-skip-permissions \
    --allowedTools "Read,Grep,Glob,Bash(cat *)" \
    --max-turns 5 \
    --no-color)

  REPORT+="## $REPO\n$RESULT\n\n"
done

echo "$REPORT" > security-audit-$(date +%Y%m%d).md
echo "Audit complete. Report saved."
